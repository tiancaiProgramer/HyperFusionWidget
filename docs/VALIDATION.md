## 0.0.5 关于页与兼容模式（2026-10-30）

- 测试手机 Xiaomi 15（24129PN74G），Android 16 / OS3.0.307.0.WOCCNXM；MiLink 17.2.5.0.2607311944，智能助理 25.31.31-07151812。同签名从 0.0.4 覆盖安装 0.0.5 / versionCode 12。
- 首页「关于」入口可进入独立页面并返回；「启用与添加」已移入该页，展开/折叠正常。「测试版本说明」与兼容开关均在「关于」中，当前深色界面排版已截图检查。
- 兼容模式关闭时，新 MiLink 版本被明确拒绝并指向「关于」；开启后无需重启进程即读取 15 台设备，关闭又恢复版本限制，缓存仍保留为上次数据。

- 11 项身份/状态、17 项展示行为、11 项 MiLink 版本策略检查（合计 39 项）、编译与 APK 签名验证通过。

## 0.0.4 设备漏项修复（2026-10-30）

- 从当前手机的 MiLink 17.2.0.1.2601081906 实现确认 `/export` 的 `max_count` 默认为 7；显式设为 128 后实机先从 7 台增加到 10 台，第 10 台风扇原生面板可以打开。
- 进一步确认：门锁与三台空调在系统设备目录中，但未入选 export 排序表。补充查询 `/category/mijia?limit=128`，仅加入普通 `mijia_iot` 设备；未修改系统设备缓存、导出表或权限判断。
- 最终实机读取 14 台，与系统导出列表加普通米家目录的去重并集完全一致。原有 7 台均保留；2 个直接执行场景未被补充，所有设备 ID 唯一。
- 快照仍仅返回原有 9 个白名单字段，不包含账号、MAC、SSID 和 privateData。原首页常驻、隐藏集合和旧排序前缀均保持不变，新读出的设备追加至完整列表。
- 列表底部可见门锁和三台空调；点击未入选 export 的门锁可以打开 MiLink 原生面板。只验证面板展示，未执行开锁、开关设备或其他控制，也未验证门锁的具体控制能力。
- 同签名覆盖安装成功，版本号 0.0.4 / versionCode 11；只重载 MiLink :ui 进程加载查询修复，负一屏宿主保持运行。既有 11 项身份/状态、17 项展示行为检查和 APK 签名验证通过。
- 最终手动刷新完成后仍为 14 台，显示「已同步系统设备列表」；原两台首页常驻与负一屏 widget ID 15 绑定保留。本轮 crash buffer 未见应用或 MiLink 新增崩溃。

## 0.0.3 本机接续验证（2026-10-30，历史修复包）

本节记录发布后的追加验证，不改变 GitHub v0.0.3 已发布 APK 的内容。先在 README 所列 MIX Fold 3 / HyperOS / MiLink / 智能助理组合上同签名覆盖安装官方 v0.0.3，再安装本地修复包复测。

- 备份原有 0.0.2 APK 和应用数据库；确认原安装包、官方 0.0.3、本地 JKS 证书一致。升级后保留 7 台设备和负一屏 widget ID 15，原常驻两台迁移正确，旧未勾选项没有变成显式隐藏项。
- 官方 0.0.3 实机复现：常驻三台时，奇数网格末尾的空白 View 使用 wrap-content 高度，在 ScrollView 中撑高最后一行，导致底部操作区出现巨大间隔。工作树将空位高度明确设为 0，保留两列宽度；修复包中三台常驻时「更多设备」、刷新和底部操作区正常可见。
- App 完整列表包含全部 7 台已读取设备及首页常驻项；隐藏一台后完整列表仍正常排版。
- 验证两台设备的隐藏和取消隐藏、隐藏自动取消常驻、隐藏栏目可常驻首页、默认折叠与展开、取消隐藏后不自动常驻。
- 验证首页长按拖动柄排序、完整列表箭头排序、隐藏列表箭头排序；数据库确认三套顺序独立，强制停止再启动后选择、隐藏状态和顺序保留。
- 手动刷新出现「已同步系统设备列表」反馈；打开手机设备的 MiLink 原生面板可见电量与原有入口，未执行响铃或设备控制。

## 0.0.2 实机验证（2026-10-30）

- 同签名覆盖安装成功；SQLite 1 → 2 升级后保留原有 7 台设备和负一屏 widget ID 15 绑定。
- 首页两列、默认常驻 2 台；「更多设备」展开 7 台并仍停留在 MainActivity，「收起设备」可恢复。
- 设置为常驻 4 台并隐藏一台后，首页展示 4 台、已选 6 台；强制停止 App 后重新启动，结果仍保留。
- 测试后已恢复常驻 2 台、全部 7 台可选；「更多操作」和「启用与添加」可展开与收起。
- 单一刷新按钮能完成同步并显示反馈，前台定时同步更新读取时间。
- 点击手机设备仍打开 MiLink 原生面板，可见电量和原有操作入口；未执行响铃或设备控制。
- 系统 PendingIntent 记录确认负一屏「更多」指向 MainActivity 的 expand 入口；发送相同 Intent 后正确展开并复用当前 App 页面，本轮未直接点击负一屏按钮。
- 窗口初始化顺序导致的首次启动异常已修正并重新覆盖安装验证。

真实新设备加入事件本轮未发生，自动加入逻辑由展示行为检查覆盖。未在本轮重新删除/添加负一屏卡片，也未逐项重测所有设备的控制操作。
