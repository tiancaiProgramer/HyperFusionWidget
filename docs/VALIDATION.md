# 验证范围

当前公开预览版本为 0.0.3。下文区分构建检查、前版已有实机验证和本版尚未完成的验证；前版结果不能替代当前界面或其他机型的兼容验证。

0.0.2 为已安装验证的本地开发版本，尚未创建公开 Release。

0.0.3 修正界面逻辑；按用户要求仅生成并发布安装包，尚未安装此版进行实机验证。

## 构建检查

- Java 编译与 Android 资源打包。
- 11 项主机 JVM 检查：签名、精确 UID、共享 UID 拒绝、其他用户拒绝、系统和 Root UID 拒绝、状态位解析及直接执行场景识别。
- 当前 17 项展示行为检查：六台与任意三台均直接常驻、全部列表包含常驻和未常驻项、隐藏栏目可常驻、隐藏和取消隐藏、三套顺序独立、新设备追加、断连保留、旧版选择迁移、空首页、去重与特殊模块约束。
- APK 签名、对齐与现代模块入口检查。
- Maven Central 编译依赖固定 SHA-256 校验。

## 已有实机验证

以下验证基于 README 所列 MIX Fold 3 / HyperOS / MiLink / 智能助理组合，在内部预览版完成：

- 模块安装、两个目标进程加载、真实设备列表读取。
- 原生负一屏 AppWidget 绑定、卡片展示、刷新与重复添加保护。
- 从负一屏点击手机设备，弹出包含电量与控制入口的原生面板。
- “更多”跳转正常，用户确认去掉中转页面后闪烁问题消失。
- App 内添加请求完成重复检查后返回；普通系统选择器没有附加按钮。

## 0.0.2 实机验证（2026-10-30）

- 同签名覆盖安装成功；SQLite 1 → 2 升级后保留原有 7 台设备和负一屏 widget ID 15 绑定。
- 首页两列、默认常驻 2 台；「更多设备」展开 7 台并仍停留在 MainActivity，「收起设备」可恢复。
- 设置为常驻 4 台并隐藏一台后，首页展示 4 台、已选 6 台；强制停止 App 后重新启动，结果仍保留。
- 测试后已恢复常驻 2 台、全部 7 台可选；「更多操作」和「启用与添加」可展开与收起。
- 单一刷新按钮能完成同步并显示反馈，前台定时同步更新读取时间。
- 点击手机设备仍打开 MiLink 原生面板，可见电量和原有操作入口；未执行响铃或设备控制。
- 系统 PendingIntent 记录确认负一屏「更多」指向 MainActivity 的 expand 入口；发送相同 Intent 后正确展开并复用当前 App 页面，本轮未直接点击负一屏按钮。
- 窗口初始化顺序导致的首次启动异常已修正并重新覆盖安装验证。

真实新设备加入事件本轮未发生，自动加入逻辑由展示行为检查覆盖。未在本轮重新删除/添加负一屏卡片，也未逐项重测所有设备的控制操作。

## 未完整验证

- 0.0.3 原生界面排版、拖动手势、持久化与升级迁移的实机表现（当前手机未连接）；JVM 模型检查不替代这些验证。
- MiLink 默认仅返回 7 台导致的设备漏项，包括用户报告的门锁；此轮明确暂不修改设备读取逻辑。
- 当前 App 内自动添加流程在删除已有卡片后重新首次放置，尚未重测。
- 所有设备种类的面板及具体控制动作。
- 桌面放置、内屏布局与折叠切换。
- 长期后台调度、锁屏恢复和网络变化后的恢复。
- 其他 HyperOS / MiLink / 智能助理版本。
- 海尔等其他平台的接入。

0.0.1 发布时没有为了修改版本号再次安装到测试手机。
