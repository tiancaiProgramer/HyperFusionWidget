# HyperFusionWidget

把 HyperOS「融合设备中心」中的设备放到负一屏卡片和桌面小组件，点击设备打开系统原生面板。

当前版本：**0.0.6**，已完成本机验证的公开预览版。应用名称为「融合设备卡片」，包名为 `dev.fusion.widget`。此版补充原生电视设备来源，实机结果见[验证范围](docs/VALIDATION.md)。

[下载 APK](https://github.com/tiancaiProgramer/HyperFusionWidget/releases/latest) · [验证范围](docs/VALIDATION.md) · [实现结构](ARCHITECTURE.txt) · [更新记录](CHANGELOG.md)

## 功能

- 显示 MiLink 导出列表、同源米家目录与原生实时列表中的电视设备、状态和可用电量，按设备 ID 去重。
- App 使用两列设备卡片，提供一个刷新入口；“更多操作”默认折叠。
- 首页「关于」集中提供「启用与添加」、测试版本说明和 MiLink 兼容模式；启用说明仍可折叠。
- MiLink 兼容模式默认开启，允许其他版本尝试连接；开关跨进程保存，手动关闭即恢复标准版本检查。没有保存过设置的新安装和升级使用开启状态，已有手动选择会保留。
- 展示设置勾选哪些模块，App 首页就直接常驻哪些模块，没有固定数量档位；首页模块支持长按拖动柄或上下箭头排序。
- “更多设备”打开 App 内的完整列表，包含已经常驻的设备；新设备自动追加至完整列表，是否常驻由用户选择。
- 设备可单独隐藏，集中收纳到默认折叠的「隐藏设备」模块；该模块也能选中常驻首页，并参与排序。
- 首页、完整列表、隐藏栏目分别保存顺序，互不影响，设备暂时消失不会清除保存的设置。
- 负一屏与桌面小组件共用首页选择和顺序，实际显示数量仍受卡片高度限制（最多 2 / 4 / 6 个模块）。隐藏模块点击后打开 App 内的隐藏栏目。
- 点击设备打开系统原生设备面板；系统完整设备中心位于“更多操作”中。
- 在 App 内一键发起负一屏添加，检查重复卡片，不向系统选择器添加额外按钮。
- 使用系统内容变化任务、曝光刷新和周期任务更新缓存。
- 无网络权限，日常运行不调用 `su`，不修改内核或系统分区。

这张卡片使用 Android RemoteViews。原生设备面板会在点击后弹出，并非嵌入卡片内部。海尔等其他平台接入仍在调研，**本版本没有海尔设备控制功能**。

## 适配范围

标准模式的实机基线如下：

| 项目 | 版本 |
| --- | --- |
| 手机 | Xiaomi MIX Fold 3 |
| HyperOS | OS3.0.304.0.WMVCNXM |
| Android | 16 |
| 设备互联 / MiLink | 17.2.0.1.2601081906 |
| 智能助理 / 负一屏 | 25.31.06-07091932 |
| LSPosed | 2.2.1 (7912)，现代 API 102 |

兼容模式另在 Xiaomi 15 / Android 16 / OS3.0.307.0.WOCCNXM / MiLink 17.2.5.0.2607311944 上验证过设备读取、手机原生面板与小组件独立进程刷新。该机智能助理为 25.31.31-07151812，其负一屏自动添加尚未验证。

适配依赖系统私有接口。默认兼容模式允许其他 MiLink 版本尝试连接，接口不同仍可能无法使用；在「关于」关闭兼容模式后恢复精确版本检查。此开关仅作用于 MiLink，智能助理的适配范围不变。不能把上述结果推广到全部 HyperOS 机型。只装 KSU 不能加载本模块，还需要支持现代 API 102 的 LSPosed 环境。

## 安装

1. 在 Releases 下载并安装 `HyperFusionWidget-0.0.6.apk`。
2. 在 LSPosed 启用「融合设备卡片」，勾选两个作用域：
   - 设备互联：`com.milink.service`
   - 智能助理：`com.miui.personalassistant`
3. 重新启动两个目标应用，或重启手机。更新模块后也需要重新加载作用域。
4. 在桌面打开一次负一屏，让原生小组件宿主初始化。
5. 打开「融合设备卡片」，刷新并确认模块连接；0.0.2 及之后的版本在「更多操作」中点击「添加到负一屏」。
6. 回到负一屏，卡片会追加到已有卡片之后。已有卡片不会重复添加。

安装或连接问题可在首页「关于 → 启用与添加」查看步骤。兼容模式默认开启；在「关于」切换开关后会立即重新检查连接，不需要为每次切换重启手机。安装新版模块后仍需先重新加载目标进程。

桌面也提供标准 AppWidget 添加入口，但桌面放置与折叠屏内屏布局尚未完成验证。

## 使用与限制

设备状态来自系统缓存，底部显示读取时间；“刷新”会发起有时限的设备发现。App 在前台时每 15 秒读取系统列表，新设备须先由系统发现。后台任务可能受系统调度限制，不能保证设备状态持续实时。

0.0.4 显式读取 `/export?max_count=128`，并补充 `/category/mijia?limit=128` 中的普通米家设备，解决默认 7 台截断和部分门锁、空调不在导出列表中的漏项。合并列表最多 128 台，按 ID 去重；补充目录不加入会直接执行的场景。新增读出的设备进入完整列表，首页常驻仍由用户选择。本机已验证从 7 台恢复为 14 台；其他机型与超出此上限的设备数量尚未验证。

0.0.6 进一步读取 MiLink 的原生电视列表，补充未写入上述目录的附近电视。手动刷新会在用户已同意 MiLink 互联隐私说明的前提下发起最长 12 秒的原生发现，只释放本模块自己的发现连接。扫描结束后，近期发现的电视在 MiLink 进程内最多保留 10 分钟；不再位于实时列表的记录显示「待刷新」，点击会重新发现并打开系统原生面板。此轮在基线 MiLink 上验证了「客厅的小米电视」，未逐一验证其他 MiLink 版本的电视接口。

锁屏时不发起设备面板请求。普通设备从当前目录中查找，电视从当前或有时限的近期发现记录中查找；原生面板继续负责重新确认设备、认证和实际控制。会直接执行的米家场景不在本版本调用范围内。其他设备类型、后台长期恢复和内外屏切换尚未逐项验证。

若显示模块未连接，检查作用域、组件版本和目标进程是否已重新加载。单设备面板不可用时，可通过「更多操作 → 打开系统设备中心」进入原生页面。

移除时，在负一屏长按删除卡片，然后在 LSPosed 禁用本模块并重新加载目标应用，最后卸载 App。

## 数据处理

桥接仅传递卡片所需字段，不转发账号凭据、MAC、SSID 或原始私有数据。专用桥接方法校验调用者 UID、唯一包绑定和签名证书；系统原有 Provider 方法保持原调用路径。没有全局禁用 Android 的签名或权限校验。

仓库只包含本项目源码和构建配置，不包含系统 APK、第三方 App 安装包、反编译代码、签名私钥、手机截图或设备缓存。

## 构建

需要 Python 3、JDK 17、Android SDK `platforms;android-35` 和 `build-tools;36.0.0`。

```sh
# 从 Maven Central 下载 libxposed API 102.0.0；脚本会验证固定 SHA-256。
python3 tools/fetch_xposed_api.py

export FUSION_JAVA_HOME="/path/to/jdk17"
export FUSION_ANDROID_SDK="/path/to/android-sdk"
python3 build.py
```

也可使用 `JAVA_HOME` 和 `ANDROID_HOME`。构建输出位于 `dist/`，包含 APK 与 SHA-256 文件；构建过程运行 11 项调用身份和状态解析检查、17 项展示行为检查、11 项 MiLink 版本策略检查、15 项原生电视策略检查，并验证 APK 签名。

Windows PowerShell 中使用 `$env:FUSION_JAVA_HOME="C:\path\to\jdk17"` 和 `$env:FUSION_ANDROID_SDK="C:\path\to\android-sdk"` 设置路径，再运行 `python tools/fetch_xposed_api.py` 与 `python build.py`。构建脚本会选择 SDK 的 `.exe` / `.bat` 工具，并使用标准 ZIP 路径保存模块入口。

libxposed 仅作为编译依赖，不打入 APK，也不纳入仓库。可用 `FUSION_XPOSED_JAR` 指定已经准备好的 API 102 JAR。

默认在 `.local/` 创建本地开发签名。自行发布时设置 `FUSION_KEYSTORE` 和 `FUSION_KEYSTORE_PASSWORD`，密钥别名为 `fusion`；可用 `FUSION_OUTPUT` 指定输出目录。调用者证书指纹随构建生成，因此所有组件必须使用同一个安装包。更新已安装版本必须保留同一签名私钥。

GitHub Actions 也会构建并运行检查。CI 产物使用临时开发签名，无法覆盖 Releases 中不同签名的安装包；日常安装请下载 Releases APK。
